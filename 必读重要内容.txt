# 项目基本类型及概述

## 项目概述
本项目是一个青春纪元模拟器游戏，包含多种游戏机制和玩法，玩家可以通过各种活动提升自己的属性，完成游戏目标。

# 液态玻璃模式 vs 默认模式的颜色配方对比

## **液态玻璃模式 (iOS 26风格)**

### **核心配方**：
```stylus
background: #FFFFFF2A                // 16.5% 透明度白色
border: 1px solid #FFFFFF33          // 20% 透明度白色边框
backdrop-filter: blur(10px) saturate(1.35)  // 较浅模糊 + 饱和度增强
```

### **多层阴影系统**：
```stylus
box-shadow:
    0 8px 24px #20268833             // 主阴影：淡蓝色（20%透明度）
    inset 0px 0px 10px #FFFFFF1A     // 内发光：白色（10%透明度）
    inset -3px 3px 4px #FFFFFF10     // 内阴影：白色（6%透明度）- 模拟玻璃厚度
    inset -0.5px 0.5px 0px #FFFFFF60 // 高光边缘：白色（37.5%透明度）- 模拟玻璃边缘反射
```

### **颜色特性**：
1. **极低透明度**：16.5%背景透明度，几乎透明
2. **柔和色调**：使用淡蓝色作为主阴影，避免纯黑色
3. **多层白色**：通过不同透明度的白色创造玻璃的层次感
4. **饱和度增强**：`saturate(1.35)`让背后内容更鲜艳
5. **边缘高光**：使用更浓的白色边缘模拟玻璃折射

## **默认模式 (传统亚克力)**

### **核心配方**：
```stylus
background: #FFFFFFB0                // 69% 透明度白色
backdrop-filter: blur(20px)          // 中度模糊
border: none                         // 无边框
box-shadow: 0px 2px 12px rgba(0,0,0,.1)  // 简洁的黑色阴影
```

### **变量系统**：
```stylus
CardBackground = #FFFFFFB0           // 69%透明度
CardBackgroundHover = #FFFFFF60      // 37.5%透明度（悬停状态）
CardBlurRadius = 20px                // 较大的模糊半径
```

### **颜色特性**：
1. **较高透明度**：69%背景透明度，保持可读性
2. **单层阴影**：简洁的黑色阴影创造立体感
3. **无边框设计**：依赖背景区分边界
4. **中性模糊**：`blur(20px)`不加饱和度调整
5. **实用主义**：强调功能性和可读性

## **核心区别对比**

| 特性 | 液态玻璃模式 | 默认模式 |
|------|-------------|----------|
| **透明度** | 16.5% (极透明) | 69% (半透明) |
| **模糊半径** | 10px (精细) | 20px (较强) |
| **饱和度** | 135% (增强) | 100% (原样) |
| **边框** | 有 (白色半透明) | 无 |
| **阴影层数** | 4层 (复杂) | 1层 (简洁) |
| **阴影颜色** | 淡蓝色 + 白色 | 纯黑色 |
| **设计理念** | 拟物化、层次感 | 扁平化、实用性 |
| **灵感来源** | iOS 26 玻璃形态 | Windows 11 亚克力 |

## **应用场景建议**

### **使用液态玻璃模式时**：
- 希望极简、现代的设计
- 背景图片需要清晰显示
- 追求拟物化的玻璃质感
- 不介意牺牲一些可读性

### **使用默认模式时**：
- 需要良好的文字可读性
- 追求实用性和功能性
- 想要清晰的界面层次
- 需要兼容性更好的设计

## **一句话总结颜色配方**：

**液态玻璃**：`16.5%透明白 + 淡蓝阴影 + 多层白色内阴影 + 10px增强模糊 + 半透明边框`

**默认模式**：`69%透明白 + 黑色外阴影 + 20px中性模糊 + 无边框`

# 代码模块化结构

## 项目文件结构

```
src/
├── components/           # 组件目录
│   ├── AchievementModal.tsx   # 成就窗口组件
│   ├── EndingScreen.tsx       # 游戏结束界面组件
│   ├── EventModal.tsx         # 事件弹窗组件
│   ├── ExamView.tsx           # 考试界面组件
│   ├── HomeView.tsx           # 主菜单界面组件
│   ├── NicknameInput.tsx      # 昵称输入组件
│   ├── SettingsModal.tsx      # 设置窗口组件
│   ├── StatsPanel.tsx         # 状态面板组件
│   ├── TalentView.tsx         # 天赋选择界面组件
│   └── VersionModal.tsx       # 版本信息窗口组件
├── data/                 # 数据目录
│   ├── achievements.ts        # 成就数据
│   ├── gameData.ts            # 游戏核心数据
│   ├── mechanics.ts           # 游戏机制数据（天赋、社团等）
│   └── versions.ts            # 版本信息数据
├── hooks/                # 自定义钩子目录
│   └── useGameLogic.ts        # 游戏逻辑核心钩子
├── types.ts              # 类型定义文件
└── App.tsx               # 应用根组件
```

## 模块职责详解

### 1. 类型定义模块 (`src/types.ts`)
- **核心职责**：定义所有TypeScript类型和接口
- **具体内容**：
  - 页面类型 (`PageType`)
  - 成就类型 (`Achievement`)
  - 版本信息类型 (`Version`)
  - 用户类型 (`User`)
  - 模态窗口类型 (`ModalType`)
  - 游戏事件相关类型 (`EventEffect`, `EventChoice`, `GameEvent`)
  - 天赋相关类型 (`Talent`)
  - 商店物品类型 (`ShopItem`)
  - 社团类型 (`Club`)
  - 周末活动类型 (`WeekendActivity`)
  - 难度设置类型 (`DifficultySettings`)
  - 游戏规则类型 (`GameRules`)
  - OI竞赛相关类型 (`OICompetition`, `OITraining`)
  - 玩家状态类型 (`PlayerState`)
  - 考试结果类型 (`ExamResult`)
  - 游戏状态类型 (`GameState`)
  - 游戏数据类型 (`GameData`)
  - 游戏结束数据类型 (`GameEndData`)
- **重要性**：为整个项目提供类型安全保障，确保数据结构一致性

### 2. 数据模块 (`src/data/`)
- **核心职责**：存储和管理游戏相关数据
- **子模块**：
  - **achievements.ts**：定义游戏成就列表
  - **gameData.ts**：存储游戏初始状态和核心数据配置
  - **mechanics.ts**：定义游戏机制相关数据（如天赋、社团、周末活动等）
  - **versions.ts**：存储版本更新信息
- **数据流向**：数据从这些文件加载到游戏逻辑中，用于初始化游戏状态和提供游戏内容

### 3. 逻辑模块 (`src/hooks/useGameLogic.ts`)
- **核心职责**：实现游戏核心逻辑和状态管理
- **具体功能**：
  - 游戏状态管理（使用React的useState）
  - 核心游戏逻辑函数（使用React的useCallback）
  - 游戏事件处理
  - 玩家状态更新
  - 游戏进度管理
  - 副作用处理（如游戏时间追踪）
- **返回值**：提供游戏状态和操作函数给组件使用
- **重要性**：整个应用的大脑，所有游戏逻辑的核心

### 4. 组件模块 (`src/components/`)
- **核心职责**：实现UI界面和用户交互
- **组件分类**：
  - **页面组件**：完整的游戏页面，如HomeView、TalentView、ExamView等
  - **模态窗口组件**：弹出式窗口，如SettingsModal、AchievementModal等
  - **功能组件**：特定功能的UI组件，如StatsPanel
- **组件特性**：
  - 每个组件都是独立的React函数组件
  - 使用TypeScript接口定义组件属性
  - 组件内部管理自身状态和逻辑
  - 通过props接收外部数据和回调函数

### 5. 应用模块 (`src/App.tsx`)
- **核心职责**：应用的入口点，管理全局状态和页面路由
- **具体功能**：
  - 导入和使用useGameLogic钩子
  - 管理用户昵称相关状态
  - 根据currentPage渲染不同的页面组件
  - 管理模态窗口的显示和隐藏
  - 处理全局事件和回调

## 模块间依赖关系

```
App.tsx ──> useGameLogic.ts ──> data/  # 应用使用逻辑，逻辑使用数据
  │           │
  │           └─> types.ts            # 逻辑依赖类型定义
  │
  └─> components/ ──> types.ts        # 组件使用类型定义
```

## 数据流向

1. **初始化阶段**：
   - 应用启动时，App.tsx加载useGameLogic钩子
   - useGameLogic从data目录加载初始数据
   - 初始化游戏状态和玩家状态

2. **运行阶段**：
   - 用户与组件交互，触发事件
   - 组件调用useGameLogic提供的回调函数
   - useGameLogic更新游戏状态
   - 状态更新触发组件重新渲染
   - 组件显示更新后的游戏状态

3. **持久化阶段**：
   - 使用localStorage存储用户昵称等持久化数据
   - 游戏状态在内存中管理，可根据需要扩展为持久化存储

## 扩展指南

### 添加新功能的步骤

1. **类型定义**：在`types.ts`中添加新的类型或扩展现有类型
2. **数据准备**：在`data`目录中添加新的数据或扩展现有数据
3. **逻辑实现**：在`useGameLogic.ts`中添加新的逻辑函数和状态管理
4. **UI实现**：在`components`目录中创建新的组件或修改现有组件
5. **应用集成**：在`App.tsx`中集成新功能，添加路由和状态管理

### 代码规范

1. **命名规范**：
   - 文件和目录：使用kebab-case（如`use-game-logic.ts`）
   - 组件名：使用PascalCase（如`HomeView`）
   - 变量和函数：使用camelCase（如`playerState`）
   - 常量：使用UPPER_SNAKE_CASE（如`MAX_HEALTH`）

2. **类型安全**：
   - 为所有变量和函数参数添加类型注解
   - 使用接口定义复杂数据结构
   - 利用TypeScript的类型推断和检查

3. **代码组织**：
   - 每个文件只包含一个主要组件或功能
   - 使用注释分隔代码逻辑块
   - 保持函数短小精悍，职责单一

4. **性能优化**：
   - 使用useCallback缓存回调函数
   - 使用useMemo缓存计算结果
   - 避免不必要的重新渲染

5. **可维护性**：
   - 编写清晰、简洁的代码
   - 添加必要的注释和文档
   - 遵循一致的代码风格

通过以上模块化结构设计，项目实现了高度的可维护性、可扩展性和类型安全性，为后续功能的添加和修改提供了清晰的结构基础。
